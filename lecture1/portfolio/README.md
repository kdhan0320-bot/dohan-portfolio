## 실행과 검사

이 작품 폴더에서 실행합니다.

```powershell
npm ci
npm run dev -- --host 127.0.0.1
npm run lint
npm run build
```

## 파일 안내

- src: 현재 화면과 동작 코드
- public: 주소로 제공되는 이미지·글꼴
- package-lock.json: 설치 버전 기록
- dist: 빌드 결과, 직접 수정하지 않음

본인 기여와 AI 지원 범위를 구분합니다. 프로젝트 상세의 공개 URL과 hash 경로는 폴더명 변경 후에도 유지합니다.

4. 화면 안에 본문 프레임을 만듭니다. **X 20 / Y 80 / W 350**. 이름은 `본문`입니다. 본문을 선택하고 **Shift+A** → 오른쪽 **Auto layout**에서 **Vertical(세로), Gap 24, Padding 0**으로 설정합니다. Width는 **Fixed 350**, Height는 **Hug contents(내용에 맞춤)**로 둡니다. 빈 프레임에서는 임시 높이를 두고 내용을 넣은 뒤 Hug로 바꿔도 됩니다.
5. T로 ‘배정 대기 요청’과 ‘냉각수 펌프 · PU-118’을 만듭니다. 오른쪽 **Typography**에서 제목 **28 / 줄 높이 36**, 보조 **14 / 20**을 입력합니다. 두 텍스트를 Shift로 함께 선택 → **Shift+A** → 세로, Gap **8**. 묶음 이름은 `제목`입니다. Layers에서 `본문` 안으로 넣고 Width를 **Fill container(부모 폭 채우기)**로 바꿉니다. 글자도 폭 Fill, 높이는 자동 줄바꿈에 맞추고 고정 높이로 자르지 않습니다.

**값을 입력하는 위치:** W/H와 X/Y는 오른쪽 Design의 크기·위치 항목, Gap/Padding은 Auto layout, 글자 크기·줄 높이는 Typography입니다. UI 언어에 따라 이름이 다를 수 있습니다. Auto Layout 안의 자식 순서·간격은 X/Y를 억지로 바꾸지 말고 Layers 순서와 Gap/Padding으로 조절합니다.

**첫 확인점:** 왼쪽 Layers에서 `M01_정보우선_390` 아래에 `상단 영역`과 `본문`이 있고, `본문` 안에 `제목`이 있는지 확인합니다. 바깥 프레임은 390×844, 본문은 X 20 / Y 80 / W 350입니다. 화면 전체가 하나의 PNG라면 편집 가능한 직접 제작 과제가 아닙니다.

### 2. 담당자·기한·실행 버튼 묶기

1. T로 ‘담당자’, ‘미배정’을 만듭니다. 라벨 **14/20**, 값 **18/26**. 함께 선택 → Shift+A → **세로 / Gap 4**. 이름은 `담당자`입니다.
2. 이 묶음을 **Ctrl+D**로 복제해 ‘완료 기한’, ‘2026.10.07’로 바꿉니다. 두 묶음을 함께 선택 → Shift+A → **가로 / Gap 16**. 이름은 `배정 정보`입니다.
3. T로 ‘담당자 선택’을 **16/24**로 입력 → Shift+A → 버튼 프레임을 만듭니다. **H 48**, 가로·세로 중앙 정렬. 기존 원본의 실행 버튼 색과 둥근 모서리 값을 사용합니다.
4. `배정 정보`와 버튼을 함께 선택 → Shift+A → **세로 / Gap 16 / 상하좌우 Padding 16**. 이름은 `배정 카드`입니다. 이를 Layers에서 `본문`의 `제목` 바로 아래에 넣습니다.
5. 바깥 카드 Width=**Fill container**, Height=**Hug contents**. 안의 `배정 정보`와 버튼 Width=Fill. 담당자·기한 두 열도 각각 Fill로 설정합니다. 버튼은 **318×48**이 됩니다. Fill이 보이지 않으면 해당 요소가 Auto Layout 부모 안에 들어 있는지 먼저 확인합니다. Fill을 설정한 뒤 W에 숫자를 다시 입력하면 Fixed로 바뀌므로, 계산값은 결과 확인용입니다.
6. 다음으로 `설비 정보`를 만듭니다. 같은 기존 사진 **96×72**와 ‘냉각수 펌프 / 조립 2라인’, ‘진동·소음 증가’를 묶습니다. 가로 Auto Layout, Gap **16**, Padding **16**, Width=Fill, Height=Hug. 사진은 Fixed, 텍스트 묶음은 Fill입니다. 긴 텍스트는 줄바꿈합니다. `본문`에서 배정 카드 아래에 둡니다.
7. 마지막에 처리 현황을 실제 텍스트로 넣습니다. ‘요청 접수 완료 / 담당자 배정 대기 / 정비 보고 예정 / 완료 확인 예정’. 16/24, 세로 Gap 12부터 시작합니다. 본문 안의 큰 묶음 간격은 24를 유지합니다.

최종 Layers 순서는 `상단 영역` + `본문(제목 → 배정 카드 → 설비 정보 → 처리 현황)`입니다. **담당자·기한·선택 버튼을 먼저 읽을 수 있는지**를 첫 번째 관찰 기준으로 삼습니다.

### 3. 사진 우선 화면 만들기

1. 직접 만든 가장 바깥 `M01_정보우선_390`을 선택 → **Ctrl+D**. 캔버스 오른쪽으로 옮기고 이름을 `M01_사진우선_390`으로 바꿉니다.
2. Layers에서 `설비 정보` 안의 사진을 `본문`의 **제목 바로 아래**로 옮깁니다. 본문과 같은 들여쓰기 수준의 자식이어야 합니다. 사진 Width=Fill, **H 196**으로 바꿉니다. 결과는 **350×196**입니다. 기존 사진의 채우기/자르기 설정으로 설비가 보이게 하고 이미지를 가로로 늘려 왜곡하지 않습니다.
3. 사진을 빼고 남은 설비 정보는 텍스트만 둡니다. 본문 순서를 **제목 → 사진 → 배정 카드 → 설비 정보 → 처리 현황**으로 맞춥니다. 사진이 두 번 반복되지 않게 합니다.
4. 두 안의 문구·색·서체·요청·기한은 동일하게 유지합니다. 사진 크기와 순서만 다르게 합니다. 각 프레임을 100%로 확인하고 담당자·기한·버튼이 844px 경계 안에 있는지 비교합니다. ‘사진은 바로 보이지만 실행 영역이 얼마나 아래로 갔는가’를 기록합니다.

### 4. 선택한 안을 320px로 조정하기

1. 자신이 선택한 안을 Ctrl+D → 이름 `M01_선택안_320` → 바깥 프레임 **W 320 / H 568**. **K(Scale)로 전체를 축소하지 않습니다.**
2. 상단 영역 **W 320**, 본문 **X 20 / Y 80 / W 280**으로 바꿉니다. 바깥은 일반 프레임이므로 이 세 값은 직접 바꿉니다. 안의 카드는 Fill이라 폭 280, 내부 버튼은 **248×48**로 따라 바뀌어야 합니다.
3. 정보 우선 안을 골랐다면 사진은 **96×72**를 유지합니다. 사진 옆 글자 공간은 좁으므로 텍스트 높이를 Hug로 두고 줄바꿈을 확인합니다. 사진 우선 안이라면 사진은 **W Fill(280) / H 157**로 줄여 같은 비율을 유지합니다.
4. 제목 28/36, 본문 16/24, 보조 14/20, 버튼 높이 48은 먼저 유지합니다. 기한은 2026.10.07을 임의로 줄이지 않습니다. 겹침이 있으면 텍스트 폭·높이와 묶음의 Hug/Fill부터 점검합니다.
5. 정보 우선 안의 실행 영역을 우선 검토하는 것을 권합니다. 사진 우선 안에서 버튼이 568px 아래로 밀린다면 억지로 글자를 줄여 숨기지 말고 그 차이를 기록한 뒤, 사진 높이·배치를 바꿀지 직접 판단합니다. 아래 처리 현황은 세로 스크롤로 이어져도 됩니다.
6. 화면 밖 본문이 보이지 않아 편집하기 어려우면 작업 중에만 Clip content를 끄고, 최종 확인 때 다시 켭니다. 바깥 프레임 오른쪽 **Prototype → Scroll behavior / Overflow → Vertical scrolling**으로 설정하고 우측 상단 **Present(재생)**에서 첫 화면과 하단 스크롤을 확인합니다. 버튼 연결은 이 세 화면 검토 뒤 진행합니다.

| 값 | 정보 우선 390 | 사진 우선 390 | 선택안 320 |
|---|---:|---:|---:|
| 바깥 프레임 | 390×844 | 390×844 | 320×568 |
| 본문 X / Y / W | 20 / 80 / 350 | 20 / 80 / 350 | 20 / 80 / 280 |
| 본문 Gap / 카드 Padding | 24 / 16 | 24 / 16 | 24 / 16부터 확인 |
| 버튼 결과 크기 | 318×48 | 318×48 | 248×48 |

[공식 Auto Layout 안내](https://help.figma.com/hc/en-us/articles/360040451373-Guide-to-auto-layout-in-Figma)에서 Shift+A, Gap/Padding, Fixed/Hug/Fill의 역할을 확인할 수 있습니다. [공식 스크롤 안내](https://help.figma.com/hc/en-us/articles/360039818734-Prototype-scroll-and-overflow-behavior)는 프레임보다 긴 내용과 세로 스크롤 설정을 설명합니다.

### 5. 세 화면과 함께 남길 비교 기록

- **관찰:** 각 화면에서 먼저 보이는 정보와 첫 화면 아래로 밀린 정보. 실제 캡처로 확인합니다.
- **선택:** 어떤 안을 골랐고, 담당자·기한·버튼의 순서를 왜 그렇게 정했는가?
- **직접 작업:** 새로 만든 레이어와 직접 조절한 값 3가지. 사진·기존 스타일 재사용, AI 안내를 따랐다는 범위도 구분합니다.
- **한계:** 실제 사용자 업무 속도·오류율은 아직 측정하지 않았다고 기록합니다. ‘이수진이 더 적합하다’ 같은 확인되지 않은 선택 근거는 추가하지 않습니다.

제출물은 **편집 가능한 세 프레임 링크 + 100% 화면 캡처 + 위 네 항목**입니다. AI 참고 원본을 본인이 만든 전(before)으로 표시하지 않습니다. 직접 만든 결과를 확인한 뒤에만 해당 작업을 포트폴리오 기여에 추가합니다.

M01 검토 후 아래를 직접 구성합니다. 모든 화면은 편집 가능한 텍스트·프레임·Auto Layout으로 만들며, 이름·사진·직무는 가상 예시임을 기록합니다. 치수는 시작 제안입니다.

선택 화면의 [참고 원본](https://www.figma.com/design/GInxTqHo6Y87DEe3vuhmMw?node-id=968-1405)은 레이어·색상 참고용입니다. ‘이수진이 더 적합하다’는 근거는 확인되지 않았으므로 추가하지 않습니다.

**프로토타입은 두 출발점으로 구분합니다.** 직접 만든 프레임의 오른쪽 Prototype에서 버튼을 다음 프레임으로 연결합니다. 정상 흐름은 `M01 → M02 기본 → M02 선택 → M03 → M05 → M06`, 오류 흐름은 별도 복제한 `M03_실패시연 → M04 → M03_재시도 → M05 → M06`입니다. 저장 대기는 시연용 지연이며 실제 저장 시간으로 표현하지 않습니다. 먼저 Instant로 연결·돌아가기를 검수하고, 필요할 때만 짧은 전환을 붙입니다. 버튼 선택 → 오른쪽 Prototype → 대상 프레임으로 연결하는 방법은 [Figma 공식 연결 안내](https://help.figma.com/hc/en-us/articles/360040315773-Connect-your-prototype)를 참고합니다.

390×844에서 흐름을 마친 뒤 320×568에서도 선택 카드·오류 안내·실행 버튼을 확인합니다. 글자 전체를 축소하지 않고 줄바꿈·그룹 간격을 조정합니다. 초기에는 실행 영역을 본문 끝에 두고 전체 세로 스크롤로 접근하도록 구성해 고정 버튼과 콘텐츠가 겹치는 문제를 피합니다.

**제출할 자료:** 비교 2안, 선택안 320px, 상태 프레임·클릭 흐름, 직접 조정한 레이어와 값 3가지, 선택 이유·한계 각 1문장, 원본/AI 도움/본인 제작 범위. 먼저 M01 세 프레임을 확인한 뒤 나머지를 진행하면 됩니다. 실제 결과물을 확인하기 전에는 포트폴리오의 본인 기여에 추가하지 않습니다.

## 이전 홈·상세 — 작품의 장면, 2026-11-12

사용자가 승인한 ‘작품의 장면’ 시안을 첫 화면으로 적용합니다. 대상은 대표작과 지원자의 실제 기여를 빠르게 파악하려는 채용 검토자입니다. 기존의 추상적인 선 그래픽과 반복 설명이 작품의 개성을 가린다는 피드백을 아래 규칙으로 반영했습니다.

- 첫 화면에서 잔상관의 실제 작품 장면을 크게 보여주며, 품의선·설비결 버튼으로 화면·설명·확인된 기여·상세 링크를 함께 바꿉니다. 자동으로 작품을 넘기지 않습니다. 모바일은 선택 버튼과 이미지가 세로로 이어지며 두 인물이 함께 보이는 구도를 사용합니다.
- 첫 진입의 제목·이미지 모션은 한 번만 실행합니다. 품의선을 선택하거나 품의선 상세를 보면 입고 3개에서 2개가 현장으로 이동하고 보유 1개가 남습니다. 상세의 이력은 완료 후 강조하며, 별도 이력 버튼으로 바로 이동할 수 있습니다. 재생 버튼·작품 전환·컴포넌트 해제 시 타이머를 정리합니다. 움직임 감소 설정에서는 정적인 최종 수량을 제공합니다.
