기준선 구현 노트

산업용 비전 검사 도입을 검토하는 사람이 검사 예시를 이해하고, 상담에 필요한 자료를 준비하도록 구성한 가상 기업 사이트입니다. Figma 디자인을 실제 HTML 요소와 반응형 웹으로 구현했습니다.

방문자의 질문에서 정한 설계 기준

  1. 01

    무엇을 검사하나요?

    검사명만으로 결함을 이해하기 어렵다고 가정했습니다. 전체 제품과 같은 사진의 확대 화면을 함께 놓고, 색상에 더해 유형별 아이콘과 이름을 표시했습니다.

  2. 02

    어디에, 어떻게 도입하나요?

    제품의 생산 단계인 ‘적용 공정’과 도입 검토 순서인 ‘도입 절차’를 분리했습니다. 각 단계는 준비 자료·검토 핵심·정리할 내용의 같은 순서로 읽습니다.

  3. 03

    무엇을 준비하면 되나요?

    선택한 검사를 상담까지 이어 주고, 변경 버튼을 명시했습니다. 잘못 입력한 항목은 오류 목록에서 바로 찾아갈 수 있으며, 안내창을 확인해도 작성 중인 값은 유지합니다.

위 문제는 프로젝트의 기획 가설입니다. 실제 제조업 담당자 인터뷰나 상담 전환율 측정으로 사용성 효과를 검증한 것은 아닙니다. 허구의 인증·고객 실적 대신 검사 예시와 준비 과정에 범위를 집중했습니다.

제작 역할

본인 — 원본 Figma 작품과 요구 범위를 제시하고, 디자인 방향과 수정 결과를 확인했습니다.

AI 지원 — HTML·CSS·JavaScript 코드 작성과 반응형·키보드 조작 보완, 도식 정리, 검수를 지원했습니다. 이미지 일부에도 AI를 사용했습니다.

역할 구분 — 결과물의 기능 검사와 본인의 독립적인 구현 능력은 별개입니다. 직접 수정하며 익힌 범위는 실제 수행한 내용으로 설명합니다.

핵심 구현 3가지

  1. 01

    반응형과 사진 구성

    PC의 좌우 배치를 모바일에서는 읽는 순서에 맞춰 쌓고, 좁은 화면의 버튼도 줄을 바꿉니다. Grid·Flex가 배치를 담당하며 검사 표시 좌표는 사진 크기에 대한 비율로 관리합니다.

    css/home.css · js/images.js

  2. 02

    이어지는 검사 선택

    세 검사의 이름·사진·설명을 한 데이터 파일에서 읽습니다. URL의 type 값으로 현재 검사를 정해 새로고침·직접 진입·뒤로가기에서도 화면과 선택이 맞습니다.

    js/data.js · js/inspection.js

  3. 03

    키보드와 폼 안내

    오류 테두리와 현재 키보드 위치를 나타내는 테두리를 따로 표시합니다. 오류 목록은 입력칸으로 연결되고, 안내창을 닫으면 열었던 버튼으로 돌아갑니다. 완료 안내를 닫을 때만 입력값과 오류 상태를 함께 초기화합니다.

    js/common.js · js/consultation.js

시연과 검증 범위

문의는 브라우저 안에서만 확인하는 시연입니다. 서버 전송·개인정보 저장·실제 상담 접수는 하지 않습니다.

수정본 검증 · 2026-11-03
최신 Figma의 검사 아이콘과 검사 변경 버튼을 반영했습니다. 로컬 수정본에서 메인·검사·상담·구현 설명을 320·390·768·1440px에서 렌더링했습니다. 네 폭에서 버튼·사진을 통한 검사 변경과 입력 유지, 초점 복귀, 빈 제출 오류, 키보드 오류 링크 이동, 완료 후 초기화를 확인했습니다. 390px에서는 검사 종류 전환·상담 연결·모바일 메뉴·도입 단계 이동도 확인했습니다.

긴 오류 문장의 불릿을 첫 줄에 맞추고, 축소된 검사 표시선의 두께를 보완했습니다. 오류 표시와 키보드 초점은 함께 보입니다. 검사 변경·개인정보 안내를 닫을 때는 입력을 유지하고, 시연 완료 안내를 닫으면 연락처·동의·오류를 초기화한 뒤 회사명으로 초점을 옮깁니다. 선택한 검사 종류는 유지합니다.

실제 휴대전화·Safari·Firefox·스크린리더·외부망 로딩 속도는 미검증입니다. 실제 검사 정확도·인증·고객 실적을 주장하지 않습니다.
