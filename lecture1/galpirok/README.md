## 공개 주소와 짧은 PC의 기록 배치

- 문제: 이전 프로젝트 이름이 공개 주소에 남아 있었고, 1280×640 지원 관리에서는 조작 영역이 여러 줄로 쌓여 첫 기록이 약 360px 아래에서 시작했다. 공개 화면 직접 점검에서 확인했다.
- 규칙: 공개 주소는 galpirok으로 통일한다. 이전 jobflow-dashboard는 같은 출처의 새 주소로 연결하고 페이지·회사·검색 조건과 인증 콜백 정보를 그대로 전달한다. 공통 포트폴리오의 기존 링크는 수정하지 않아도 연결된다. 이전 HTML 캐시의 버전 확인 파일과 기존 복구 스크립트 두 개도 구주소에 유지한다.
- 규칙: 폭 1000px 이상에서는 회사 목록·달력·검색·보류함을 한 줄로 묶는다. 모바일 단계 탭과 기존 제목 위치는 유지한다.
- 호환성: 이메일 인증 복귀는 기존 jobflow-dashboard 콜백 주소를 유지한 뒤 새 주소로 연결한다. 실제 Supabase 허용 주소를 임의 변경하지 않는다. 기존 계정 식별값과 저장소 키도 유지한다. 실제 인증 메일·계정 저장 검증과 샘플 검증은 별개다.

## 체험과 기록지의 설계 기준

- 문제: 체험 버튼 뒤에서 다시 체험을 시작해야 하고, 모바일에서는 선택한 전형 단계가 약하게 구분됐다. 공개 화면 직접 점검에서 확인한 사항이다.
- 규칙: 홈의 주 버튼은 선택한 회사의 준비 체크를 바로 연다. 회사 기록 미리보기는 읽기 전용으로 유지하며, 두 경로 모두 같은 가상 기록을 사용한다. 준비가 없는 회사는 할 일 추가부터 시작한다.
- 규칙: 모바일 전형 탭은 같은 폭을 유지하고 단계명과 개수를 두 줄로 구분한다. 선택 상태는 기존 보라색 면과 흰 글자로 표시하고 키보드 초점도 유지한다.
- 규칙: 진한 청회색 회사 색인, 연한 청회색 날짜표, 민트 계열 다음 준비 라벨로 정보의 역할을 구분한다. 결과·보류 회사에는 다음 준비를 노출하지 않는 기존 기준을 유지한다.
- 기여: 사용자는 문제와 수정 우선순위를 결정했고, AI 도구는 코드·화면 조정과 검증을 수행했다. 사용성 개선 효과를 제3자 실험이나 성과 수치로 검증한 것은 아니다.

## 면접 질문 선택의 설계 기준

- 문제: 대상 선택이 필터 버튼 안에 숨겨져 있고, 펼치면 질문과 답변이 아래로 밀렸다. 모바일 선택창은 제목 없이 순번만 보여줬다. 공개 화면 점검과 사용자 피드백으로 확인했다.
- 규칙: 왼쪽 위에 질문 대상을 항상 표시한다. 전체·공통·회사별 범위로 목록을 좁히고, 주제는 필터가 아닌 기록의 보조 정보로 유지한다. 기존 주제 데이터와 편집 기능은 보존한다.
- 규칙: 모바일 질문 선택창에는 현재 질문 제목과 해당 범위의 순번·전체 개수를 표시한다. 긴 제목은 선택창에서만 줄이고 전체 제목은 질문 본문과 펼친 목록에서 읽는다. 질문이 하나면 같은 위치에 제목과 1 / 1을 일반 기록 정보로 표시한다. 화살표·비활성 표시·불필요한 키보드 초점을 없애고 긴 제목도 읽을 수 있게 줄바꿈한다.
- 안전장치: 작성 중 대상·질문 전환을 막고, 회사가 바뀐 기록을 저장하면 그 대상에서 이어서 확인한다. 짧은 화면의 답변 편집에서는 기존 취소·저장 영역을 우선한다.
- 기여: 사용자는 직접 노출 방식과 우선순위를 결정했고, AI 도구는 구현·코드 검사·화면 점검을 수행했다. 제3자 사용성 검증 결과로 표현하지 않는다.

## 기록지 마감 기준

- 문제: 단일 질문이 흐린 선택창으로 보여 읽기 어려웠고, 회사 색인과 기록 제목 사이 간격·모서리가 화면마다 조금씩 달랐다.
- 규칙: 조작할 수 없는 정보는 선택창처럼 보이지 않게 한다. 회사 색인은 기존 청회색과 접힌 모서리를 유지하고, 기록 카드·준비 제목·편집창에는 같은 비대칭 모서리 기준을 사용한다.
- 규칙: 면접 목록 제목과 답변 기록의 안쪽 간격을 맞추고, 회사 정보와 질문 본문은 가는 구분선 하나로 구별한다. 색이나 기능을 추가하지 않는다.
- 기여: 사용자는 문제와 수정 방향을 결정했다. AI 도구가 코드와 스타일을 수정하고 샘플 동작·화면을 점검했다. 실제 계정 저장이나 제3자 사용성 평가를 대신하지 않는다.
