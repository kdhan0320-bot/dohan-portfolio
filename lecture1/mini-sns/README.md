# Mini SNS

작업을 기록하고, 스터디에 참여하고, 대화를 이어가는 작은 커뮤니티 체험 작품입니다.

[공개 사이트](https://kdhan0320-bot.github.io/dohan-portfolio/mini-sns/)

## 최종 완성 상태

**2026-11-08 사용자 확정: 미니 SNS 최종 완성본.** 작업 기록과 피드백을 연결하는 프런트엔드 체험 작품으로 이번 개선을 마무리했습니다. 포트폴리오 대표 작품 목록에는 편입하지 않습니다.

기능·화면 기준은 [b75646d](https://github.com/kdhan0320-bot/dohan-portfolio/commit/b75646dcdfa4e46533f59d70d6cfcde1b24c72cc)입니다. [최종 작업 기록](docs/HISTORY.md)에 기획 의도, 디자인 특징, 구현 범위, 실제 검수 결과와 미검증 범위를 정리했습니다. 이후 개선은 실제 사용에서 확인한 문제나 별도 요청을 기준으로 진행합니다.

## 실행과 검사

기존 설치된 의존성을 사용합니다. 이 작품 폴더에서 실행합니다.

```powershell
npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
npm run lint
node --test src/utils/communityState.test.js src/utils/feedLocation.test.js
node tests/responsive-upload.mjs
node tests/record-accessibility.mjs
node tests/feed-continuity.mjs
node tests/lighter-records.mjs
npm run build
```

브라우저 검사는 기존 `tools/site-audit-kit`의 Playwright와 설치된 Edge를 사용합니다. 기본 검수 주소는 `http://127.0.0.1:5174/`이며 실행 중인 서버가 필요합니다. `MINI_SNS_URL` 환경 변수로 검사할 주소를 지정할 수 있습니다. 검사 데이터는 별도 브라우저 세션에만 작성합니다.

## 현재 구현 범위

- 피드 분류·검색, 게시물 상세·이미지 확대, 좋아요·북마크
- 댓글 작성·수정·삭제와 반응 수치 연동
- 제목·내용 검증, 샘플 이미지 선택, JPG/PNG/WebP 로컬 첨부(1.5MB 제한), 태그 정리
- 새 기록·수정 초안 자동 보관, 주소로 다시 연 기록 수정, 삭제 확인
- 모임 참여·탈퇴와 인원 수, 프로필 활동 수, 대화방 접근의 동일 상태 사용
- 대화 입력·목록 미리보기·읽음 상태·한글 입력 처리
- 목적지가 있는 활동 알림과 읽음 처리, 프로필 수정
- PC의 메뉴·피드·보조 영역, 모바일의 하단 메뉴 및 대화 전용 레이아웃
- 브라우저 저장 오류 안내, 없는 기록·미참여 대화방·검색 결과 없음 상태

이 작품은 프론트엔드 체험용입니다. 예시 인물·게시물·모임·기존 반응은 시연 데이터이며, 실제 회원가입·서버 API·DB·다른 사용자와의 실시간 대화는 구현하지 않았습니다. 기록과 첨부 이미지, 프로필, 참여, 대화, 초안은 현재 브라우저의 localStorage에 저장합니다. 다른 기기와 동기화되지 않으며 브라우저 데이터 삭제 시 사라집니다.

기존 소개 페이지의 대표 포트폴리오 목록 편입은 이번 작업 범위가 아닙니다.

## 문제와 설계 근거 — 2026-11-08 개선

대상은 작업 중의 화면과 고민을 공유하고 가벼운 스터디를 찾는 디자인·프론트엔드 학습자입니다. 기존 배포 화면에서 직접 관찰한 문제를 기준으로 개선했습니다. 사용자 조사를 수행했다거나 취업 성과가 검증되었다고 주장하지 않습니다.

| ------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------- |

## 기록 형식과 시각적 개성 — 후속 개선

대상은 완성 전 작업을 공유하며 구체적인 의견을 얻고 싶은 학습자입니다. ‘어떻게 기록해야 할지 막막함’은 이번 설계의 가설이며, 실제 사용자 조사로 검증된 사실로 표시하지 않습니다.

- **기록:** 01 시도한 것 → 02 바꾼 이유 → 03 의견이 필요한 부분. 첫 내용만 필수로 두고 이유·질문은 선택으로 남겨 작성 부담을 제한했습니다. 질문·스터디 분류에서는 첫 두 칸의 문구를 상황에 맞게 바꿉니다.
- **피드백 연결:** 작성한 질문을 게시물의 의견 요청 영역과 댓글 창에 함께 표시합니다. 이유는 피드에서 펼쳐 읽고 상세 화면에서는 바로 읽습니다. 새 필드는 초안·수정·새로고침·검색에도 반영됩니다.
- **시각 규칙:** 겹친 종이, 접힌 모서리, 01·02·03 표식을 진입 화면·기록 카드·작성 화면·보조 안내·모임·프로필·로고·파비콘에 연결했습니다. 남보라는 시도와 주요 행동, 갈색은 선택의 이유, 녹색은 대화를 표시합니다. 색만으로 구별하지 않고 번호와 문구를 함께 사용합니다.
- **가독성:** 작은 일반 UI 문구는 최소 12px, 주요 본문은 15px, 모바일 입력은 16px로 정리했습니다. 흐린 회색을 짙은 보조색으로 바꾸고 입력창과 선택 상태의 경계를 강화했습니다.
- **키보드:** 분류·활동 탭에 방향키·Home·End·하나의 Tab 진입점·연결된 패널을 적용했습니다. 모바일 메뉴의 표시 순서와 키보드 순서를 맞추고 경로 이동 시 본문으로 초점을 옮깁니다. 댓글 작성·수정·삭제 후 초점을 보존하며 새 댓글은 목록 안에서 보입니다.
- **기존 기록 보존:** 이전 형식의 작성 글과 초안을 읽을 수 있습니다. 수정되지 않은 예시 게시물에만 이유·질문을 보강하고, 사용자가 바꾼 본문·반응·삭제 상태는 보존합니다.

방향과 반영 범위는 사용자가 결정·승인했고, 이번 구체적인 화면 설계·코드·예시 문구·검수는 AI가 수행했습니다. 이 결과를 사용자 개인의 단독 창작이나 조사 성과로 표현하지 않습니다. 브랜드 인지도나 피드백 품질의 향상은 아직 사용자 실험으로 확인하지 않았습니다.

- 프로필 수정 및 저장 목록·수치 연결 확인.
- 모임 참여→대화방 이동, 인원 수 일치, 대화 입력·목록 반영·새로고침 후 유지 확인.
- 새 기록 작성·태그 중복 정리, 수정 주소에서 새로고침 후 편집, 초안 복원, 기록 삭제 후 피드 복귀와 없는 기록 안내 확인.

## 탐색 복귀와 초안 마감 — 2026-11-08

- 검색어와 분류를 URL에 함께 보존합니다. 검색 입력은 현재 주소를 갱신하고 분류 전환은 이동 기록에 남깁니다. 새로고침·브라우저 뒤로가기·상세의 피드 복귀에서 같은 조건을 유지합니다.
- 피드에서 작성·수정으로 이어진 경우에도 원래 검색 조건을 복귀 주소로 전달합니다. 복귀 주소는 피드 내부의 허용된 조건만 사용합니다.
- 작성 중 나갈 때 ‘초안 보관하고 나가기’, ‘계속 작성’, ‘초안 버리기’를 구분합니다. 기본 키보드 초점은 보관 버튼입니다. 수정 초안을 버려도 등록된 원본 기록은 유지합니다.
- 초안 보관·삭제에 실패하면 이동하지 않고 오류를 알립니다. 기존 제목·시도·이유·질문·첨부 데이터는 그대로 유지합니다.
- 추가 검사: 1440·390·320px에서 검색 복귀, 분류와 검색의 조합, 초기화, 초안 보관·삭제·복원, 수정 원본 보존, 기록의 질문→댓글 연결을 확인했습니다. 저장 차단 상황에서 초안 보관·삭제 실패와 복구도 확인했습니다.
- 이번 보완은 앞서 확정한 겹친 기록지와 01 시도·02 이유·03 질문의 디자인을 유지합니다. 실제 사용자 조사나 실시간 커뮤니티로 검증한 결과는 아닙니다.

## 가볍게 읽고 쓰기 — 2026-11-08 마감

대상은 모바일에서 여러 작업을 훑어보고 짧은 기록을 남기는 학습자입니다. 기존 화면에서 첫 게시물이 길고 필수 입력 이후에도 선택 항목을 모두 지나야 등록할 수 있었던 문제를 관찰했고, 사용자가 두 가지 개선을 승인했습니다.

| 접힌 입력이 사라지거나 수정할 내용을 놓칠 수 있음 | 접기와 데이터 삭제를 분리하고 기존 내용은 먼저 보여줌 | 접어도 입력·첨부가 유지되고 등록에 포함됨. 기존 글·초안에 내용이 있는 그룹은 자동으로 펼침. Enter·Space로 여닫고 Tab으로 입력 |

- 겹친 기록지, 01·02·03과 세 가지 색을 유지합니다. 작은 이미지도 비율을 보존하며 잘라내지 않고, 확대해서 볼 수 있습니다. 상세 화면에서는 전체 내용을 읽습니다.
- 첨부 오류는 이미지 선택 영역 바로 아래에 표시합니다. 접기·펼치기에는 키보드 초점 표시를 적용하고 펼친 입력창의 카드 안쪽 여백을 확인했습니다.
- 390×844 CSS px, 같은 예시 데이터와 빈 작성 화면 기준으로 첫 게시물 높이 약 859→587px, 작성 페이지 전체 높이 약 1,852→1,139px를 확인했습니다. 화면 길이의 변화이며 작성 시간·만족도 향상을 측정한 수치가 아닙니다.
- 확인: 320·390·430·767·768·1440px에서 요약→전체 기록, 접힌 내용의 등록, 선택 입력 생략, 초안·수정 시 자동 펼침, 키보드 조작, 펼친 입력창의 경계를 검사했습니다. 기존 75개 반응형 검사·첨부 오류/복원·검색 복귀·저장 단위 검사 9개도 통과했습니다. 390·1440px에서는 펼친 작성 화면을 포함해 UI 텍스트 크기와 대비를 검사했습니다.
- 시각 검토: 모바일 피드, 접힌/펼친 작성 화면, 태블릿·PC 화면. 실제 사용자의 다양한 글과 모든 휴대전화 사용성을 검증한 결과는 아니며, 실기기 가상 키보드와 Safari·Firefox는 미검증입니다.
- 구체적인 구현과 검수는 AI가 수행했습니다. 새 패키지나 서버·DB 연결은 추가하지 않았습니다.
