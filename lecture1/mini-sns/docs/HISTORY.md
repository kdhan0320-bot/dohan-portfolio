### 기획 의도

작업 중의 화면과 고민을 공유하는 디자인·프론트엔드 학습자를 위한 작은 기록 공간입니다. 완성된 결과뿐 아니라 오늘 시도한 것, 선택한 이유, 다른 사람에게 묻고 싶은 부분을 남기고, 그 질문을 댓글로 이어가는 경험을 목표로 했습니다. 피드에서 관심 있는 작업을 찾고 스터디와 대화로 이어지는 흐름도 체험할 수 있습니다.

기록 형식은 **01 시도한 것 → 02 바꾼 이유 → 03 의견이 필요한 부분**으로 정리했습니다. 제목과 첫 기록만 필수이며, 이유·질문·이미지·태그는 선택입니다. 질문과 스터디 분류에서는 입력 문구를 상황에 맞게 바꿉니다.

‘기록할 내용을 정리하기 막막할 수 있다’는 설계 가설입니다. 실제 화면에서 관찰한 정보 과밀·긴 입력 과정·탐색 조건 소실과 구분하며, 사용자 조사나 사용성 향상 수치로 표현하지 않습니다.

### 관찰한 문제와 설계 결정

| 관찰한 문제 | 설계 규칙 | 최종 화면·동작 |
| --- | --- | --- |
| 일반적인 제목·본문만으로 작업의 고민이 드러나기 어려움 | 시도·이유·질문을 구분하되 추가 입력을 강제하지 않음 | 세 단계 기록 형식, 질문이 이어지는 댓글 창 |
| 모바일에서 안내와 긴 게시물이 탐색을 늦춤 | 핵심을 먼저 보여주고 전체 내용으로 연결 | 본문·질문 두 줄 요약, 비율을 보존한 작은 이미지, ‘기록 전체 보기’; 상단 중복 작성 유도를 줄이고 하단 작성 버튼 유지 |
| 짧은 기록도 선택 항목을 모두 지나야 등록 가능 | 필수 내용을 먼저 작성하고 나머지는 필요할 때 펼침 | ‘이유와 질문’, ‘이미지와 태그’ 두 그룹. 접힌 제목에 작성·첨부 상태 표시 |
| 접힌 내용이나 이동 중인 초안을 잃을 수 있음 | 접기와 삭제를 분리하고 기존 내용은 다시 열 때 노출 | 접어도 입력·첨부를 보존하고 등록에 포함. 내용이 있는 초안·수정 그룹은 자동 펼침. 보관·계속 작성·버리기 구분 |
| 상세를 보고 돌아오면 탐색 맥락이 끊김 | 검색어·분류를 복귀 주소에 보존 | 상세·작성·수정에서 원래 피드 조건으로 복귀, 새로고침과 뒤로가기 대응 |
| 작은 보조 글자·약한 경계·키보드 이동의 불일치 | 읽기와 조작 기준을 여러 화면에 일관되게 적용 | 주요 본문 15px, 일반 UI 최소 12px, 모바일 입력 16px. 초점 표시·탭 키보드 조작·팝업 초점 복귀 |

모바일은 빠른 훑어보기를 우선하고, PC·상세 화면은 작업의 맥락을 읽는 구성을 유지했습니다. 선택 항목을 여는 단계는 추가되지만 기본 작성 부담을 줄이며, 작성된 내용은 상태 표시와 자동 펼침으로 확인할 수 있도록 했습니다.

### 디자인 특징

- **기록지 모티프:** 겹친 종이와 접힌 모서리를 로고·파비콘·진입 화면·기록 카드·작성 화면·프로필·보조 안내에 연결했습니다.
- **세 단계의 의미:** 남보라는 시도와 주요 행동, 갈색은 선택의 이유, 녹색은 질문과 대화에 사용합니다. 색과 함께 번호·문구를 제공해 역할을 구분합니다.
- **읽기 중심의 화면:** 따뜻한 중립 배경, 가는 경계, 정돈된 여백으로 본문과 행동의 위계를 만듭니다. 모바일 요약에서도 글자 크기와 주요 조작 영역을 유지합니다.
- **일관된 질문 표현:** 기록의 녹색 질문 영역과 댓글 창의 질문 안내를 연결해 어떤 의견을 남기면 되는지 보여줍니다.
- **시연용 자산:** 샘플 작업 이미지는 이 작품을 위해 만든 SVG 콘셉트 이미지입니다. 실제 고객 작업이나 다른 이용자의 작업으로 표시하지 않습니다.

익숙한 종이와 SNS 구성 요소를 목적에 맞게 조합한 시각 정체성입니다. 독보적인 시각 언어나 브랜드 인지도가 검증됐다고 주장하지 않습니다.

실제 회원가입·서버 API·DB·기기 간 동기화·다른 이용자와의 실시간 통신·푸시 알림은 구현 범위에 없습니다. ‘이미지 첨부’는 서버 업로드가 아니며, 브라우저 데이터 삭제 시 저장 내용도 사라집니다.

### 한계와 마무리 기준

- AI가 수행한 검수에는 실제 휴대전화의 가상 키보드, Safari·Firefox 실기기, 스크린리더 전반의 검증이 포함되지 않았습니다. 사용자의 모바일 직접 확인은 위에 별도로 기록했습니다.
- 텍스트 검사는 로고·비활성 컨트롤·샘플 이미지 안의 글자를 제외한 표본 검사이며, 전체 WCAG 적합성 인증이 아닙니다.
- 실제 사용자 조사, 장기 운영, 다양한 이용자 콘텐츠, 서비스 규모에서의 성능·효과는 검증하지 않았습니다.
- 최종 평가는 **목적이 분명하고 시각 규칙과 주요 동작이 일관된 체험 작품으로 마무리할 수 있다**는 판단입니다. 채용 성과나 운영 서비스 수준을 보장하는 평가로 사용하지 않습니다.
- 이번 개선에서 요청한 범위는 완료했습니다. 이후에는 실제 사용에서 반복되는 불편이나 새 요구가 확인될 때 별도 개선으로 다루며, 완성을 위해 기능·장식을 계속 추가하지 않습니다.

사용자는 목적·우선순위·개선 방향과 최종 완성 여부를 결정했습니다. 이번 개선의 구체적인 화면 설계·코드·예시 문구·검수와 기록 정리는 AI가 수행했습니다. 아래 초기 교육 과정의 제작 이력과 이번 개선을 구분하며, 전체 결과를 사용자 개인의 단독 창작이나 조사 성과로 표현하지 않습니다.

### 제작 목적

모바일 SNS 앱의 핵심 화면 흐름을 학습하기 위해 교육 과정에서 처음 만든 결과물을, 실제 백엔드 없이도 주요 인터랙션을 체험할 수 있도록 게스트 데모 흐름과 mock 데이터, 프론트엔드 상태 관리(React Context) 구조로 개인적으로 재정리했습니다.

홈 피드, 게시글 작성, 프로필, 모임, 채팅, 알림 화면을 하단 탭 내비게이션으로 연결해 사용자가 여러 기능을 자연스럽게 이동할 수 있도록 구성했습니다.

---

### 주요 기능

- 게스트 데모 진입
- 홈 피드
- 게시글 작성 / 수정 / 삭제 (메모리 상태)
- 피드 이미지 확대 모달
- 좋아요 토글 (메모리 상태)
- 댓글 작성 / 수정 / 삭제 (메모리 상태)
- 프로필 화면
- 모임 목록
- 모임 참가 후 채팅방 이동
- 채팅 목록 / 채팅방 상세
- 메시지 입력창 하단 고정
- 알림 화면
- 하단 탭 내비게이션
- 반응형 모바일 앱 레이아웃

### 게스트 데모

로그인 화면의 `게스트 데모 시작하기` 버튼을 누르면 별도의 회원가입·로그인 절차 없이 바로 주요 화면을 체험할 수 있습니다.

- 표시 이름: 데모유저
- 아이디 표기: @demo_user

---

### 데모 데이터와 한계

이 프로젝트는 모바일 화면 흐름과 프론트엔드 상태 관리를 정리한 학습 기록이며
실제 운영 서비스가 아닙니다. 현재 취업용 포트폴리오 공개 작품에도 포함하지
않습니다.

- 실제 회원가입·로그인 기능이 없습니다.
- 자체 백엔드와 데이터베이스를 사용하지 않습니다.
- 게시글·댓글·좋아요 변경은 브라우저 메모리에서만 동작하며, 프로필은 준비된 데모 정보를 표시합니다.
- 새로고침하면 처음 준비된 mock 데이터로 복원됩니다.
- 모임·채팅·알림 화면도 모두 mock 데이터로 구성되어 있으며, 실시간 통신 기능은 없습니다.
- 실제 이미지 업로드, 실시간 채팅, 푸시 알림 기능은 제공하지 않습니다.
