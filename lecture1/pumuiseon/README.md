# 품의선 — 부품 구매·입출고 관리

[공개 사이트](https://kdhan0320-bot.github.io/dohan-portfolio/pumuiseon/)

엑셀·메일의 구매 요청을 확인하고 종이 결재 서류를 작성해 팀장·사장님 승인을 받은 뒤 업체에 발주를 전달했던 실무 경험에서 출발했습니다. 포토센서·근접센서의 받은 날짜·수량과 현장 지급 날짜·대상을 기록하던 업무를 웹 화면으로 연결합니다.

**브라우저 저장 기반 시연**입니다. 실제 AI·권한 인증·결재 서버·업체 주문·메일·DB에 연결하지 않습니다. 사용자가 실무 경험·방향·시연 범위를 정했고 AI가 설계·구현·검증을 보조했습니다. 실제 업무 시간 절감이나 외부 사용자의 이해도가 검증됐다고 표현하지 않습니다.

## 시연 자료와 제한

- 대표 품의 `PR-2001`: 즉시 교체 2개 + 다음 정비 3개로 포토센서 5개 구매. 받은 3개 중 2개 지급 → **보유 1개 / 미입고 2개**. 품의는 사내 승인, 발주는 승인 후 업체에 주문한 기록입니다.
- `PR-2007`: 수량 2→3EA, 합계 96,000→144,000원의 재결재 예시. 실제 동시 사용자가 아니라 역할을 바꿔 확인하는 시연입니다.
- 저장은 해당 브라우저의 localStorage에 한정됩니다. 기기·사용자·탭 간 동기화하지 않으며, 읽을 수 없는 기존 자료는 덮어쓰지 않고 임시 샘플을 표시합니다.
- ‘메일·메모로 초안 만들기’는 한 품목의 명시된 값을 읽는 규칙 기반 추출입니다. 실제 LLM·OCR·파일 업로드가 아닙니다. 자동 승인·주문은 하지 않습니다.
- EA 정수 단위·보관 장소 1곳으로 제한합니다. 생산 계획/BOM·복수 창고·실사·반품·발주 취소·회계·정산·입출고 확정 기록 수정/삭제는 구현 범위가 아닙니다.

## 처음 방문하는 사람에게 확인할 5분 테스트

목표는 **구매 이유·보유 재고·미입고·변경 내용을 설명 없이 찾는지** 확인하는 것이다. 아직 실제 참여자를 대상으로 실행한 결과는 없다.

1. 기존 작업에 참여하지 않은 사람 3명 안팎에게 한 명씩 보여준다. PC 또는 모바일 한 환경에서 먼저 진행하고 사용 환경을 기록한다. 샘플을 수정하지 않은 별도 브라우저 프로필/시크릿 창에서 시작한다. 남아 있는 개인 시연 기록을 초기화하지 않는다.
2. “이 화면을 처음 본 상태에서 정보를 찾아주세요. 생각나는 대로 말해 주세요. 사람을 평가하는 테스트는 아닙니다.”라고 안내한다. 아래 질문만 읽고 메뉴·숫자·정답은 먼저 알려주지 않는다.
3. 찾지 못하면 약 1분 후 도움 필요로 기록한다. 도움을 준 시점과 내용을 남기고 이후 결과는 독립 성공으로 세지 않는다.
4. 마지막에 “가장 헷갈린 말이나 화면은 무엇인가요?”를 묻는다. 동의 없이 이름·녹음·민감한 정보를 수집하지 않는다.
