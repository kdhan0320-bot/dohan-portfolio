# 품의선

구매 요청·결재·발주·입고·지급을 연결하는 브라우저 저장 시연입니다.

[공개 사이트](https://kdhan0320-bot.github.io/dohan-portfolio/pumuiseon/)

## 실행과 검사

이 작품 폴더에서 실행합니다.

```powershell
npm ci
npm run dev -- --host 127.0.0.1
npm run lint
npm run build
```

기존 업무 규칙 테스트: `node --test tests/*.test.mjs`

## 파일 안내

- src: 현재 화면과 동작 코드
- public: 주소로 제공되는 이미지·글꼴
- package-lock.json: 설치 버전 기록
- dist: 빌드 결과, 직접 수정하지 않음

품의선의 시작점은 src/main.jsx → src/procurement/ProcurementApp.jsx입니다. 이전 커뮤니티 앱 코드는 백업 후 정리했습니다. 실제 AI·권한 인증·결재 서버·업체 주문·DB에 연결하지 않는 브라우저 저장 시연입니다.

## 전표와 재결재 정보의 설계 규칙

- 문제: 재결재 변경 내용을 확인하기까지 긴 스크롤이 필요했다. 규칙: PC와 모바일 모두 2차 이상 품의는 제목 바로 아래에 이전 제출본과 비교한 변경 요약을 표시한다. 수량과 합계를 우선하며, 전체 변경 비교로 이동한 뒤 기존 결재 순서를 따른다. 이전 기록이 없거나 변경이 없으면 그 사실을 표시한다.
- 문제: 메뉴별 아이콘·보조 제목·표 머리글의 크기와 표현이 달랐다. 규칙: 구매·결재, 발주·입고, 자재·지급, 업체 관리에 같은 전표 틀과 업무별 선 그림을 사용한다. 보조 제목은 한글 대장명, PC 표 머리글은 60px 높이·14px 글자와 같은 격자로 통일한다. 열 비율은 각 데이터에 맞추고 모바일에서는 기존 카드형 읽기 순서를 유지한다.
- 사용자 요구와 첨부한 구매 품의 대장 이미지를 기준으로 정리했다. 기존 청회색·파랑과 업무 동작은 유지하며, 이 변경 자체를 사용자 이해도나 처리시간 개선의 검증 결과로 표현하지 않는다.

- 문제: 구매 목록에서 금액·날짜만 가까워 보이고, 금액의 보조 문구 때문에 제목 기준선이 달랐다. 규칙: PC는 날짜 열의 최소 폭을 144px로 확보하고 날짜 머리글·값을 가운데 정렬한다. 금액은 오른쪽, 상태는 왼쪽 정렬해 날짜 양옆의 분리감을 맞춘다. 별도 금액 안내 줄은 두지 않고 머리글은 60px 높이의 한 줄로 유지한다. 부가세 포함 여부는 작성·상세와 모바일 금액 안내에 표시하고, 모바일의 첫 품의 위치는 유지한다.
- 문제: 같은 요청 날짜를 목록에서는 ‘필요일’, 작성·상세에서는 ‘희망 납기일’로 달리 불렀다. 규칙: 구매 목록·모바일 카드·발주 전 안내도 ‘희망 납기일’로 통일하고, 발주 후 도착 예정인 ‘입고 예정일’과 구분한다.

- 문제: 홈 전표의 안내 문장까지 링크여서 보이는 조작과 클릭 범위가 달랐다. 규칙: 안내 문장은 일반 텍스트로 두고 ‘대표 품의 보기’만 링크로 제공한다. 높이 44px의 터치 영역과 키보드 초점 표시를 유지하며 상세에서 돌아오면 같은 링크로 초점을 복귀한다.
- 문제: 업체 라벨의 둥근 모양과 점 장식이 품의·발주와 달랐다. 규칙: 공통 문서 라벨의 크기·테두리·접힌 모서리를 공유하고, 업체의 기존 색과 VN 번호로 종류를 구분한다.

- 문제: 열 간격을 조정하면서 구매 목록 전체를 1120px로 좁혀 다른 메뉴와 바깥 정렬이 달라졌다. 규칙: 구매 목록의 제목·검색·표는 다른 메뉴와 같은 본문 폭을 사용한다. PC는 표 좌우 여백 20px, 열 사이 간격 12~28px를 두고 머리글과 행에 같은 열 비율을 적용한다. 금액은 오른쪽, 날짜는 가운데 정렬하며 반복 자재명 정리와 모바일 카드 배치는 유지한다.
- 문제: 품의명 아래 반복 자재명으로 행이 높아졌다. 규칙: 목록은 품의명을 먼저 표시하고 문서번호·부서를 둘째 줄에 묶는다. 자재명 검색과 상세 품목은 유지한다. PC 행은 최소 88px이며 긴 제목은 생략하지 않고 줄바꿈한다. 모바일도 빈 행을 남기지 않고 금액·날짜를 바로 이어 배치한다.

## 공개 주소

새 주소는 /dohan-portfolio/pumuiseon/이다. 이전 /portfolio-feedback-hub/와 /my-community/는 새 주소로 이동하며 품의·발주·자재 상세 경로와 검색 조건을 유지한다. 같은 도메인의 브라우저 저장 키를 유지하므로 기존 시연 데이터도 이어진다. 공통 포트폴리오 소스는 변경하지 않았다.

## 처음 방문하는 사람에게 확인할 5분 테스트

목표는 **구매 이유·보유 재고·미입고·변경 내용을 설명 없이 찾는지** 확인하는 것이다. 아직 실제 참여자를 대상으로 실행한 결과는 없다.

1. 기존 작업에 참여하지 않은 사람 3명 안팎에게 한 명씩 보여준다. PC 또는 모바일 한 환경에서 먼저 진행하고 사용 환경을 기록한다. 샘플을 수정하지 않은 별도 브라우저 프로필/시크릿 창에서 시작한다. 남아 있는 개인 시연 기록을 초기화하지 않는다.
2. “이 화면을 처음 본 상태에서 정보를 찾아주세요. 생각나는 대로 말해 주세요. 사람을 평가하는 테스트는 아닙니다.”라고 안내한다. 아래 질문만 읽고 메뉴·숫자·정답은 먼저 알려주지 않는다.
3. 찾지 못하면 약 1분 후 도움 필요로 기록한다. 도움을 준 시점과 내용을 남기고 이후 결과는 독립 성공으로 세지 않는다.
4. 마지막에 “가장 헷갈린 말이나 화면은 무엇인가요?”를 묻는다. 동의 없이 이름·녹음·민감한 정보를 수집하지 않는다.

| 순서 | 참여자에게 읽을 질문 | 시작 화면 |
| --- | --- | --- |
| 1 | 이 사이트는 어떤 일을 할 때 쓰는 곳 같나요? | 홈 |
| 2 | 포토센서는 왜 5개를 구매했나요? 근거를 찾아 설명해 주세요. | 홈 |
| 3 | 지금 현장에 바로 줄 수 있는 포토센서는 몇 개인가요? 앞으로 도착할 것은 몇 개인가요? | 홈 |
| 4 | ‘추가 설비 포토센서 구매’는 이전 제출 때와 무엇이 달라졌나요? | 해당 품의 상세를 열어 제공 |

진행자만 보는 확인 기준: ① 구매·결재·입출고 업무를 관리하는 곳 ② 즉시 교체 2개 + 다음 정비 3개 ③ 보유 1개 / 미입고 2개, 받은 3개 중 2개는 이미 지급 ④ 수량 2→3EA, 합계 96,000→144,000원, 사유 구체화. 똑같은 문장을 말하는지보다 의미와 찾은 근거를 확인한다.
