## 실제 경험 → 문제 → 설계 규칙

사용자가 확인한 실제 경험: 엑셀·메일 요청 정리·확인 → 종이 결재 서류 작성 → 팀장·사장님 결재 → 본인이 업체에 발주 전달. 이후 센서의 입고 날짜·수량과 지급 날짜·대상을 기록했습니다. 아래 효과는 해결 가설이며 실제 업무 시간 절감이나 사용자 조사 결과가 아닙니다.

| 같은 자재·업체 정보를 다시 입력 | 등록 정보를 고르고 문서에 복사해 보관 | 자재 선택 시 규격·기준 단가·기본 업체 입력. 승인본은 이후 목록 수정과 분리 |

## 화면과 시연 범위

- `#/`: 처리 대기, 미입고, 최근 입고·지급. 기존 홈 업무 흐름 설명과 별도 홈 메뉴 제거.
- `#/requests`, `#/requests/new`, `#/requests/:id`, `#/requests/:id/edit`: 요청 작성·보완, 역할 전환, 순차 결재, 반려 종료, 승인 후 변경 시 재결재.
- `#/orders`, `#/orders/:id`: 승인된 요청만 발주일·예정일 등록, 실제 입고일·이번 받은 수량 기록. 발주 자체는 재고를 늘리지 않습니다.
- `#/materials`, `#/materials/:id`: 자재 등록·수정, 보유/미입고 수량, 입고·지급 이력, 지급일·부서·받는 사람 기록, 구매 요청 연결.
- `#/vendors`, `#/vendors/:id`: 업체 등록·수정, 관련 자재와 구매·발주 내역.
- 기존 `#/approvals`는 결재 진행 목록으로 유지하며 주 메뉴는 구매·결재로 통합. `#/about` 및 이전 팁 경로는 업무 현황으로 연결.
- 샘플: 포토센서·근접센서·제어 릴레이·리미트 스위치, 가상 업체 2곳. PR-2007은 포토센서 2→3EA의 재결재 예시입니다.

## 의도적으로 제한한 범위

EA 정수 단위·보관 장소 1곳으로 한정합니다. 생산 계획/BOM·복수 창고·재고 실사·반품·발주 취소·회계·세금계산서·금액 정산은 없습니다. 입출고 확정 기록의 수정·삭제도 제공하지 않습니다. 전사 ERP가 아닌 구매·입출고 업무를 연결한 프런트엔드 구현 사례입니다.

선택 기능인 ‘메일·메모로 초안 만들기’는 한 품목의 명시된 값만 읽는 **규칙 기반 추출**입니다. 실제 LLM·문서 업로드·OCR이 아닙니다. 등록된 이름·규격이 정확히 일치해야 자재를 연결하며, 없는 날짜 등은 사용자가 채웁니다.

자료는 이 브라우저의 localStorage에 저장되며 다른 기기·사용자·탭과 동기화하지 않습니다. 이전 요청과 제출·결재 이력은 자재·업체 식별자를 추가해 보존하고 새 센서 샘플을 추가합니다. 기존 ID와 샘플 ID가 겹치면 기존 자료를 우선해 샘플 입출고를 붙이지 않습니다. 읽을 수 없는 자료는 덮어쓰지 않고 임시 시연을 엽니다. 실서비스에는 서버 권한·동시성 처리·감사 기록·백업이 별도로 필요합니다.
