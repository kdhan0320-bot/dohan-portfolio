## 처음 확인하는 분께

1. 홈 또는 로그인의 **샘플 체험하기**에서 **오늘의 지원**을 엽니다.
2. **지원 현황**에서 회사를 등록하고 **마감 일정 → 준비 체크 → 면접 연습**을 확인합니다.
3. 샘플은 **2026-09-27 기준 가상 데이터**입니다. 편집 내용과 미저장 초안은 현재 탭 메모리에만 남고 새로고침·탭 종료 시 사라집니다.

서비스 목적·사용법은 아래 현행 안내를 따릅니다. 누적 작업 기록은 문서 끝의 접힌 이력에 보존했으며, 그 안의 ‘현재’·‘이번’·버튼 이름·검사 수치는 **해당 작업 당시**를 뜻합니다.

## 제작 목적

여러 회사에 지원할 때 흩어지기 쉬운 지원 현황과 준비 작업을 한곳에서 관리하는 것이 목적입니다. SNS나 커뮤니티가 아니라 개인의 지원 데이터 정리와 상태 관리에 집중하며, 로그인 사용자의 실제 데이터와 방문자가 둘러보는 고정 샘플을 분리합니다.

## 주요 기능

- 로그인 / 이메일 확인 회원가입(Supabase Auth)
- 로그인 사용자별 지원 회사 CRUD(Supabase PostgreSQL + RLS)
- 회사·직무 검색 / 전형별 분류 / 별도 보류함 / 등록 최신순 표시
- 네 전형 칸과 별도 보류함
- 할 일 분류와 완료 체크
- 면접 준비 메모와 중요도 / 복습 완료 관리
- 작성 요청문(브라우저 내 로컬 템플릿 구성·편집·복사, 같은 탭의 화면 이동 중 내용 유지)
- 설정에서 회사·준비 체크·면접 기록을 JSON 파일로 내려받기
- 모바일 / 태블릿 / 데스크톱 반응형 UI
- 가상 샘플을 브라우저 메모리에서 편집·체험하는 게스트 모드

## UX/UI 포인트

- 헤더는 갈피록 글자로고로 표시하고, 단계 탭·선택 표시에 갈피 정체성 유지
- 상태 Chip으로 지원 흐름을 빠르게 파악
- 지원 현황·체크리스트·면접 메모를 연결해 다음 행동 판단 지원
- 회사·직무 검색과 전형별 분류로 지원 회사 탐색
- 모바일에서는 전형 탭과 가까운 마감 목록을 먼저 표시하고 날짜 탐색은 펼쳐 사용
- 샘플 대시보드로 회원가입 전 제품 범위 확인
- 작성 요청문으로 자기소개서·면접 답변용 텍스트 구조화, 다른 화면을 다녀와도 같은 탭에서 이어서 작성

## 게스트 모드 안내

홈과 로그인 화면의 **샘플 체험하기**는 모두 **오늘의 지원**으로 이동합니다. 회원가입 없이 가상 데이터로 회사·준비할 일·면접 질문과 답변을 추가·수정·삭제할 수 있습니다. 홈 미리보기에서 특정 회사 기록을 열면 해당 회사 상세로 바로 이동합니다. 버튼은 마지막 방문 화면으로 돌아가는 기능이 아닙니다.

- 지원 현황, 체크리스트, 면접 메모, 전형 보드의 샘플은 실제 사용자 데이터가 아닙니다.
- 조회, 검색, 전형별 분류, 등록 최신순 표시, 문서 작성용 로컬 템플릿 생성은 게스트 모드에서도 동작합니다.
- 8개 지원 샘플에는 서로 다른 `created_at`이 있어 등록 최신순의 실제 표시 순서를 확인할 수 있습니다.
- 샘플의 변경은 React 메모리에서만 유지되고 새로고침 또는 설정의 샘플 초기화 시 사라집니다. 샘플 변경으로 Supabase 요청을 보내지 않습니다.
- 샘플 데이터 자체는 브라우저 저장소에 저장하지 않으며, `sessionStorage`의 `jobflow-guest-mode` flag는 현재 탭의 샘플 이용 여부만 나타냅니다. 이메일 전송 대기 정보와 계정용 회사 초안은 별도의 저장 정책을 사용합니다.
- 로그인 화면과 비밀번호 도움 화면을 왕복하는 동안 현재 탭의 샘플 기록과 작성 초안을 유지합니다. 실제 계정으로 로그인하면 샘플의 미저장 할 일·면접 초안과 작성 요청문은 지워집니다. 샘플과 계정 데이터는 병합하지 않습니다.
- 샘플 기준일은 **2026-09-27**입니다. 실제 오늘 날짜나 실제 지원 회사의 마감으로 해석하지 않습니다.

계정 모드는 Supabase Auth session과 사용자별 RLS를 사용하는 DB 저장 코드가 구현돼 있습니다. 이번 개선 검증은 샘플·코드 범위이며, 실제 계정의 인증·DB 저장과 재접속 후 유지까지 다시 확인한 것은 아닙니다.

## 데이터 경계

| 테이블 | 현재 프런트엔드 사용 범위 |
| --- | --- |
| `jobflow_profiles` | 로그인 사용자의 선택적 이름·목표 직무 설정 |
| `applications` | 지원 회사, 상태, 제출물, 메모 |
| `portfolio_checklists` | 포트폴리오 체크리스트 |
| `interview_notes` | 면접 준비 메모 |
| `application_notes` | DB에는 있으나 현재 프런트엔드에서는 사용하지 않음 |
| `prompt_templates` | DB에는 있으나 현재 프런트엔드에서는 사용하지 않음 |

`jobflow_profiles`는 JobFlow 전용 테이블이며 Community의 `profiles`와 공유하지 않습니다. profile row가 없어도 지원 회사·체크리스트·면접 메모 CRUD는 동작합니다. 해당 테이블의 `user_id`는 `jobflow_profiles`가 아니라 Supabase `auth.users(id)`를 기준으로 하며, RLS가 로그인 사용자별 행 접근을 제한합니다.

설정의 이름·목표 직무는 현재 계정의 프로필 조회에 성공한 뒤에만 편집·저장할 수 있습니다. 조회 실패 시 기존 정보를 빈 값으로 덮어쓰지 않도록 입력과 저장을 막고 다시 불러오기를 제공합니다. 이 보호 경로의 검증은 코드 테스트 범위입니다.

문서 작성 도우미는 별도 테이블에 저장하지 않고 브라우저에서 로컬 템플릿 텍스트를 만듭니다. 제품 runtime에서 LLM 또는 AI API를 호출하지 않으며, 생성된 텍스트는 사용자가 원하는 작성 도구에 직접 붙여넣습니다. 제작 과정에서 사용한 생성형 AI 코딩 보조 도구와 제품 runtime 기능은 별개입니다.

작성 요청문의 입력·생성 결과·수정한 결과는 샘플과 계정별로 분리한 현재 탭 메모리에만 보관합니다. 다른 화면으로 이동했다 돌아오면 이어서 작성할 수 있지만, 새로고침·탭 종료 후 복원은 제공하지 않습니다. 샘플 초기화와 계정 전환 시 해당 초안을 정리하며, localStorage·sessionStorage·DB에는 저장하지 않습니다. 필요한 내용은 복사해 별도로 보관해야 합니다.

문서 작성 도우미의 canonical route는 `/document-helper`입니다. 기존 `/ai-prompt` 링크는 호환을 위해 canonical route로 이동하는 `replace` redirect alias로 유지합니다.
