# 기준선 — 산업용 비전 검사 웹퍼블리싱

기존 Figma 작품을 HTML·CSS·JavaScript로 구현한 가상 기업 사이트입니다. 디자인 구현, 반응형, 기본 상호작용과 마감 품질을 보여주는 것이 목표입니다. 제출용 설명은 [구현 노트](implementation.html)에서 간단히 읽을 수 있습니다.

## 실행·공개 상태

이 폴더에서 아래 명령을 실행하고 <http://127.0.0.1:4178/>을 엽니다. 패키지 설치나 빌드는 필요 없습니다.

```powershell
python -m http.server 4178 --bind 127.0.0.1
```

ES module을 사용하므로 HTML을 `file://`로 직접 열지 않습니다. 종료는 실행한 터미널의 Ctrl+C입니다.

공개 주소: <https://kdhan0320-bot.github.io/dohan-portfolio/gijunseon/>

홈 제품 소개·도입 절차 확장본에 상담 오류 처리·모바일 간격·구현 설명 마감을 반영한 버전입니다. 사용자가 확인한 수정본을 기존 Pages workflow로 게시하며, `projects/gijunseon` 전체를 `_site/gijunseon`으로 복사합니다. 최신 게시 결과는 [배포 기록](https://github.com/kdhan0320-bot/dohan-portfolio/actions/workflows/deploy.yml)에서 확인할 수 있습니다. 공통 포트폴리오·다른 작품·패키지·workflow는 이번 변경 범위가 아닙니다.

## 제작 역할

- **본인:** 원본 Figma 작품과 요구 범위 제시, 디자인 방향 선택, 수정 결과 확인.
- **AI 지원:** 코드 작성, 반응형·접근성 보완, 도식 정리와 검수. 사용자의 독립적인 코딩 능력을 검증했다고 주장하지 않습니다.

Figma 상담 프로토타입은 기존 정상 화면에서 빈 값으로 제출하면 오류 화면으로 이동합니다. 오류 요약 4개와 각 필드의 안내를 표시하고, 고정 예시 입력을 클릭하거나 동의란을 선택하면 해당 오류가 사라지며 목록과 간격이 갱신됩니다. 오류색 `#a32f25`·배경 `#fff7f4`와 초점 표시(요약 `#236caa`, 필드 `#923a27`)를 분리했습니다. PC·모바일 각각 4개 항목의 오류 유무 16개 조합을 일반 그룹으로 구성했고, 새 오류 화면의 자동 레이아웃은 0개이며 기존 A 로고를 유지했습니다.

Figma 입력은 고정 예시를 선택하는 시연입니다. 자유 입력·이메일 형식 검사·실제 DOM 접근성 동작은 웹에서 구현합니다. 검사 변경도 Figma에서는 목록의 3개 행 중 하나를 바로 선택하지만, 웹에서는 브라우저 기본 선택 목록에서 고른 뒤 확인합니다. 같은 흐름을 검토하되 실제 입력 방식은 다릅니다.

Figma 오류 화면은 상태에 따라 최상위 화면 높이를 바꾸면 PC 그림과 클릭 영역이 어긋나는 현상이 재현되어 최대 높이를 고정했습니다. 투명한 하단 경계도 추가해 스크롤 범위를 고정한 뒤, 오류 링크가 올바른 항목으로 이동하는지 다시 확인했습니다. 폼 내부와 푸터 앞 간격은 오류 상태에 따라 갱신되지만, 오류를 해소한 뒤 푸터 아래에 캔버스 여백이 남습니다. 이 제한은 Figma 시연 화면에 해당하며 웹은 변경하지 않았습니다.

[모바일 프로토타입 실행](https://www.figma.com/proto/3ZJ4TUGqBNAewsJYzheOWo?node-id=821-241&scaling=min-zoom&content-scaling=fixed&hide-ui=1)은 Figma 제어 UI를 숨긴 링크입니다. 뷰어 상단 제어 바가 사이트 메뉴 영역과 겹치는 것을 확인했고, 기본 뷰어에서 검은 화면도 재현됐습니다. UI를 숨긴 새 세션의 메인·상담 메뉴와 제어 바 아래쪽 클릭은 정상 동작했습니다. 검은 화면의 정확한 원인은 확정하지 않았으며, 웹 메뉴 오류로 단정하지 않습니다.

Figma는 PC → 모바일 → 팝업 순서로 정리했습니다. 이번 수정 부분과 모바일 화면·팝업은 일반 그룹으로 묶었으며, 모바일에는 자동 레이아웃이 없습니다. 화면 틀과 사진 자르기에 필요한 프레임은 남겼습니다. 그룹을 더블클릭해 글자·이미지·벡터를 직접 수정할 수 있습니다. 수정하지 않은 기존 PC 본문의 자동 레이아웃은 유지했습니다.

최종 동기화에서는 모바일 검사 3종의 밑줄형 탭·설명 문구와 강조색·유형별 상담 배경·벡터 아이콘, 준비 안내의 아이콘 카드를 현재 웹에 맞췄습니다. 모바일 검사·공정·상담의 A 로고 선 굵기도 통일했습니다. 기존 화면 ID와 연결을 유지하고 일반 그룹을 사용했으며, Figma의 고정 예시 입력·검사 선택 방식은 위에 설명한 차이를 유지합니다.

기존 `gongjeongbom`의 정적 구조, 본문 바로가기, 안내창 초점 복귀와 폼 오류 패턴을 재사용·단순화했습니다. 구형 제품 데이터·스타일은 사용하지 않았으며 기존 작품 소스는 보존했습니다.

## 핵심 구현 3가지

1. **반응형과 이미지:** Grid·Flex로 정보 순서와 배치를 조정합니다. 메뉴 900px, 홈 600px, 검사 700px, 도입 단계 760px, 상담 본문 820px 등 콘텐츠에 맞는 분기점을 사용합니다. 검사 표시와 2배 확대는 원본 628×471 좌표를 비율로 바꿔 사진의 같은 부위를 가리킵니다. 큰 사진에는 크기별 WebP를 제공하고 전체·확대 사진은 같은 파일을 재사용합니다.
2. **일관된 선택 상태:** 세 검사 종류를 `js/data.js`에서 관리합니다. 탭·사진·설명·상담 선택을 URL의 `type`과 연결해 직접 진입과 뒤로가기를 지원합니다. 도입 절차의 단계 이동은 HTML 앵커로 동작합니다.
3. **키보드와 시연 폼:** 방향키·Home/End, 보이는 초점, 안내창의 Tab 순환·Escape·초점 복귀를 구현했습니다. 필수 값·이메일·시연 확인란을 검사하고 오류 요약에서 입력칸으로 이동합니다. 준비 안내를 읽은 뒤에도 입력값·동의·검사 선택을 유지합니다.

원본의 예시 입력 동작은 실제 편집 가능한 폼으로 바꿨습니다. 검사 사진 아래에는 대상·확인 포인트·준비 자료를 보완하고, 홈 요약과 별도 도입 절차의 역할을 구분했습니다. A 심볼과 도식은 별도 SVG로 정돈했으며 원본 자산은 보존합니다. 전체 화면을 이미지로 붙이지 않고 제목·본문·메뉴·탭·폼을 HTML로 구성했습니다.

## 시연과 한계

가상 기업이며 실제 인증·고객사·검사 정확도·실적·후기를 주장하지 않습니다. 원본 콘셉트 이미지에는 AI 이미지가 포함돼 있습니다. 인쇄 예시는 바코드 판독 결과가 아니며 실제 검사 조건은 샘플 검토가 필요합니다.

폼은 브라우저에서만 검증합니다. 실제 전송·메일·API·DB·회원·결제·관리자 기능이 없고, 연락처를 저장하지 않습니다. URL에는 검사 종류만 포함합니다. 예시 연락처로 연습하세요. JavaScript를 끄면 기본 메뉴·푸터·정적 예시를 볼 수 있지만 검사 전환·안내창·폼 완료는 사용할 수 없습니다.

## 검증 기록

**2026-10-18, 모바일 간격·입력 오류 마감 단계의 로컬 Chromium 검사입니다.**

- 홈·적용 공정·검사 3종·도입 절차·상담·구현 노트의 8화면을 320·390·768·1440px에서 렌더링했습니다(32개). 가로 넘침·누락 이미지·페이지/콘솔/HTTP 오류는 관찰하지 못했습니다. 변경된 모바일 제목·사진·검사 표시와 문서 캡처를 직접 확인했습니다.
- 핵심 동작 22개가 통과했습니다. 메뉴·탭·URL·뒤로가기·키보드·필수 오류·안내창·입력 유지·비전송을 포함합니다. 완료 시 POST·fetch/XHR·문서 이동·요청 본문 없이 로컬 글꼴 GET만 관찰했습니다.
- 이메일 오류→정상 입력→동의 첫 클릭을 4폭에서 별도 재현했습니다. 오류가 입력 중 갱신되고 첫 클릭이 유지됐습니다. 구현 노트의 내부 이동 6회와 외부 링크 속성을 확인했으며 외부 페이지 이동은 실행하지 않았습니다.
- Figma 모바일 상담에서 검사 변경·선택 사진 전환·빈 값 오류·예시 입력·동의·개인정보 안내·완료 안내 흐름을 직접 확인했습니다.
- Figma 모바일 메인 메뉴 → 검사 3종 탭 → 선택 검사를 유지한 상담 이동, 준비 안내 열기·상담 복귀, 적용 공정·도입 절차 이동과 단계 내부 스크롤을 직접 확인했습니다. 모바일 흐름의 PC 화면 목적지는 남아 있지 않습니다.

이전 배포본 `a74b508`에서는 공개 주소의 핵심 동작 22개와 링크 이동 132개, 원본 97개 자산의 해시를 확인했습니다. 위 항목은 모바일 간격·입력 오류 마감 단계의 로컬 검증 기록이며, 공개 배포 후 검사는 별도로 구분합니다. 로컬 검증 자료는 `closing-layout-results.json`, `closing-validation-results.json`, `fix-local-behavior-results.json`입니다.

**2026-10-18, 최종 포커스 보완**

- 후속 검토에서 오류 상태 동의란의 테두리가 키보드 초점 표시를 덮는 문제를 발견했습니다. 오류 표시는 `box-shadow`, 초점은 `outline`으로 분리해 기존 색상으로 함께 표시합니다.
- 320·390·768·1440px의 로컬 Chromium에서 오류 상태 전후 화면, Tab·Shift+Tab 이동, Space 선택·해제와 오류 복귀를 확인했습니다. 가로 넘침·콘솔·페이지·HTTP 오류는 관찰하지 못했습니다. 근거는 `focus-patch-local-results.json`입니다.

실제 휴대전화·Safari/Firefox·스크린리더·외부망 성능은 미검증입니다. 기존 `site-audit-kit`의 Playwright·Chromium을 재사용했으며 검사 파일과 캡처는 작업공간 `tmp/gijunseon-deploy-qa`에 보관합니다. 추가 패키지나 서비스 런타임 검증 코드는 넣지 않았습니다.

**2026-10-18, 불릿·확대 표시선 마감**
