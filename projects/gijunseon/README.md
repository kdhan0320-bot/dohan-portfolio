# 기준선 — 산업용 비전 검사 웹퍼블리싱

최신 Figma를 실제 HTML 요소로 구현한 가상 기업 포트폴리오입니다. 홈의 제품 소개·검사 3종·도입 검토 요약, 공정별 안내, 별도 도입 절차와 상담 시연으로 구성합니다. HTML·CSS·JavaScript ES modules만 사용하며 설치할 패키지나 빌드 과정이 없습니다.

제출용 설명은 [구현 노트](implementation.html)에서 읽을 수 있습니다. 기업 사이트와 분리한 정적 문서이며, 각 페이지 하단의 ‘구현 설명 보기’로도 이동합니다. 코드 작성·반응형·접근성 보완과 검수에는 AI 코딩 지원을 활용했습니다. 사용자의 독립적인 설명·수정 능력을 검증했다고 주장하지 않습니다.

## 실행

이 폴더에서 다음 명령을 실행한 후 <http://127.0.0.1:4178/>을 엽니다.

```powershell
python -m http.server 4178 --bind 127.0.0.1
```

HTML 파일을 직접 더블클릭하는 `file://` 방식은 ES module 제한 때문에 사용하지 않습니다. 서버 종료는 실행한 터미널의 Ctrl+C입니다. 다른 포트를 사용해도 모든 내부 경로는 상대 경로로 동작합니다.

## 공개 배포

공개 경로는 <https://kdhan0320-bot.github.io/dohan-portfolio/gijunseon/>입니다. 구현 설명은 같은 경로의 `implementation.html`에서 제공합니다.

홈 제품 소개·별도 도입 절차 확장본은 사용자 미리보기 확인과 배포 승인을 받은 버전입니다. 기존 GitHub Pages 배포 경로와 workflow를 사용하며, 기준선 외 프로젝트 소스는 변경하지 않습니다.

사용자의 기준선 commit·push·deploy 승인에 따라 기존 GitHub Pages workflow에 `_site/gijunseon` 정적 복사 단계만 추가했습니다. `main`에 push하면 기존 배포와 함께 이 경로에 반영됩니다. 공통 포트폴리오와 다른 작품의 소스·목록·경로는 변경하지 않습니다. 패키지·lockfile·Secrets·계정 설정도 변경하지 않습니다.

## Figma 대비 보완

- 최초 원본은 PC 1440px 기준이었습니다. 모바일 메뉴, 1열 검사 사진, 압축한 상담 선택 카드, 제목 아래 별도 사진 크롭은 웹 반응형을 위해 추가했습니다. 후속 승인으로 홈·도입 절차의 390px 화면과 모바일 메뉴·준비 안내를 Figma에도 정리했습니다. 장비의 주요 부분과 글자 가독성을 함께 유지합니다.
- 원본 입력칸을 누르면 예시값이 채워지는 동작을 실제 입력 가능한 폼으로 변경했습니다. 빈 값·이메일 형식·필수 동의를 검증하고 오류 요약에서 해당 필드로 이동할 수 있습니다.
- 원본의 선택 상태와 이동 흐름에 키보드 방향키·Home/End, 포커스 표시, dialog 내부 Tab 순환·Escape·초점 복귀, 본문 바로가기와 reduced motion을 보완했습니다.
- 상담 화면에 준비 안내 바로가기와 전송하지 않는다는 문구를 가까이 배치했습니다. 완료창도 ‘상담 요청 시연 완료 / 실제 전송 없이 화면 흐름을 확인했습니다’로 표시합니다.
- 사진·로고·개념도·아이콘의 Figma 원본을 로컬에 보존했습니다. 후속 피드백에 따라 웹의 로고 후보와 도입·공정 도식은 별도 SVG로 정돈했습니다. 전체 화면 스크린샷을 UI로 쓰지 않았습니다. 텍스트·버튼·탭·폼은 HTML입니다.
- 검사 사진 아래에 ‘검사 대상·확인 포인트·상담 전 준비’를 추가했습니다. 실제 판정 결과나 정확도를 주장하지 않으며 인쇄 예시와 바코드 판독을 구분합니다. 홈 도입 과정에도 각 단계에서 확인할 내용을 한 문장씩 보완했습니다.
- 상담 중 준비 안내를 읽고 ‘상담 입력 계속하기’를 누르면 페이지 이동 없이 마지막 입력 항목으로 돌아옵니다. 입력값·동의·검사 선택과 오류 상태를 그대로 유지합니다. X·Escape로 닫으면 안내를 연 버튼으로 돌아갑니다.
- 기본 메뉴·푸터·본문 바로가기는 HTML에 두어 JavaScript가 꺼져도 페이지 이동이 가능합니다. 검사 페이지의 비JavaScript 화면은 표면 흠집 정적 예시로 제한하며, 입력 폼은 전송 버튼을 비활성화합니다.
- 원본 사진은 보존하고 웹용 크기별 이미지를 추가했습니다. 원본 97개 자산의 해시가 변경되지 않았음을 확인했습니다. 하단에 가상 기업 포트폴리오 표시와 구현 설명 링크를 추가했습니다.

CSS의 분기점은 실제 콘텐츠가 좁아지는 지점에 맞췄습니다. 공통 메뉴는 900px, 홈 세로 배치는 600px, 검사 상세는 700px, 도입 단계는 760px, 상담 본문은 820px 등에서 전환합니다. 320·390·768·1440px은 **검사한 화면 폭**이며 분기점과 다릅니다.

검사 상세에서는 628×471 원본 좌표를 비율로 변환합니다. 같은 사진을 200%로 확대하고 crop 위치만 바꾸므로 두 사진의 검사 부위가 연결됩니다. 탭의 선택과 URL `type`을 함께 변경해 직접 진입과 브라우저 뒤로가기를 지원합니다.

사진 크기를 조절할 때는 CSS 박스만 보지 않고 `object-fit: cover` 및 2배 확대에 필요한 해상도를 반영합니다. 예를 들어 모바일 메인 사진은 마감 후 높이 260px에 원본 비율 3:1이므로 `sizes`에 780px를 사용합니다. 전체·확대 사진은 동일한 후보를 선택해 파일 요청을 재사용합니다.

## 시연과 데이터

가상 기업이며 실제 인증·고객사·정확도·실적·후기를 주장하지 않습니다. Figma의 개인 콘셉트 프로젝트 이미지(AI 이미지 활용)를 사용했습니다. 실제 검사 판정 조건은 샘플 확인이 필요하다는 원본 안내를 유지합니다.

폼은 submit 기본 동작을 막고 화면 안에서만 검증합니다. `fetch`, 메일 발송, API·DB·회원·결제·관리자 기능이 없습니다. 연락처를 localStorage/sessionStorage/cookie에 기록하지 않습니다. URL에는 검사 종류만 들어갑니다. 개인정보 동의 역시 시연이며 실제 수집 동의로 사용하지 않습니다. 예시 연락처로 연습하세요.

## 이전 구현의 검증과 한계

아래 검증 기록은 별도 도입 절차 페이지와 홈 제품 소개를 추가하기 전의 구현을 대상으로 합니다. 새 범위의 검증 결과는 실제 실행한 뒤 별도로 기록합니다.

- 로컬 Chromium에서 홈·공정·검사·상담을 320·390·768·1440px, 배율 1로 렌더링하고 실제 캡처를 시각 검토했습니다.
- 가로 넘침, 이미지 로드, 콘솔·페이지 오류, 공통 폰트 로드를 검사했습니다. 검사 상세 1440px 사진은 원본과 같은 x80/732, y416, 628×471입니다.
- PC/모바일 메뉴·앵커 이동, 본문 바로가기, 준비 안내 열기/닫기, 검사 3종 클릭·방향키·Home/End·뒤로/앞으로·직접 URL·상담 전달을 검사했습니다.
- 폼 필수 4항목·공백·잘못된 이메일·오류 링크·정상 완료·검사 변경·개인정보 안내·Escape·초점 복귀·전송 요청 부재를 검사했습니다.
- 실제 스마트폰, Safari/Firefox, 화면낭독기 음성 출력, 운영 환경 성능 지표는 미검증입니다. Figma와 픽셀 단위로 동일하다고 보증하지 않으며 모바일 배치는 사용자 최종 확인 대상입니다.

기존 `site-audit-kit`의 설치된 Playwright/Chromium을 재사용했으며 패키지를 추가하지 않았습니다. 검증 스크립트와 캡처는 작업공간의 임시 QA 파일로 두었고 서비스 런타임에는 포함하지 않았습니다.

## 면접 설명 3가지

1. **디자인을 구조로 번역:** Figma의 고정 위치를 그대로 복사하지 않고 Grid/Flex·공통 토큰으로 바꿔, 원본 1440px 배치와 콘텐츠 기반 반응형을 함께 구현했습니다.
2. **이미지와 선택 상태의 일관성:** 원본과 2배 크롭의 검사 좌표를 비율로 관리하고, 탭·URL·상담 종류가 같은 데이터를 사용하도록 연결했습니다.
3. **접근성과 시연의 정직성:** 키보드 탐색·dialog 초점·오류 요약을 구현하고, 실제 접수가 없는 시연이라는 사실을 입력 전과 완료 시점에 명확히 알립니다.

## 직접 연습할 2곳

1. `js/data.js`의 `details` 문구를 한 문장 더 길게 바꾸고 3종 탭·직접 URL에서 설명이 맞게 바뀌는지 확인하세요. 320/390px의 줄바꿈도 살펴봅니다.
2. `js/consultation.js`의 `fieldError()`에서 회사명 최소 글자 수 조건과 오류 문구를 추가해 보세요. 빈 값·한 글자·정상 입력·키보드 오류 이동까지 직접 시험합니다.

폰트는 공식 Google Fonts의 Noto Sans KR 400·500을 로컬 WOFF2로 보관합니다. 전체 TTF(10.4MB) 대신 unicode-range로 필요한 글자 구간만 요청합니다. 전체 124개 구간은 3.51MB이며, 현대 한글 음절 11,172개를 포함해 문구를 수정해도 지원합니다. 외부 CDN은 런타임에 요청하지 않습니다. 원본 TTF는 보존 자료로만 남겨 두었고 SIL Open Font License는 `assets/fonts/OFL.txt`에 있습니다. 실제 배포 시 네트워크 성능 측정은 별도입니다.
